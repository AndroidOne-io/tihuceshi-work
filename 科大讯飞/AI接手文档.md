# 科大讯飞 · AI for Science 视频工程 —— AI 接手文档（从 0 到 1）

> 写给接手这个工程的 AI（或人）。读完这一份就能：在本地把整条视频渲染出来、看懂每一秒画面和声音是怎么来的、按用户的要求改任何一处。
> 仓库：`https://github.com/AndroidOne-io/tihuceshi-work`，分支 **`xunfei-ai4s-edit`**。本文所有路径都相对仓库根目录。

---

## 0. 先读这里：五分钟上手

1. 这是一条 **约 4 分 18 秒、1920×1080、30fps** 的中文科普视频，主题是 AI for Science，结合 2026 科大讯飞全球 1024 开发者节。作者（用户）是 B 站 / 抖音 UP 主「AI阿亮」。
2. **整条视频没有剪辑软件工程文件，全部由 Python 代码逐帧生成。** 画面、口播拼接、配乐、音效、字幕都在代码里。改视频 = 改代码 + 重新渲染。
3. 入口是 `科大讯飞/代码/full.py`；一键出成片是 `科大讯飞/代码/render_all.py`。
4. 一切时间都挂在一张**事件表 `EV`** 上（某个字被说出来的那一刻、某个镜头开始的那一刻）。画面动画、音效、配乐的卡点都引用 `EV`，所以**改停顿、换口播，后面所有东西会自动跟着走**，不要手写绝对秒数。
5. 用户对风格和沟通有明确的硬性要求，见第 11 节，**改之前必须先读**。

## 1. 环境搭建

### 1.1 Mac

```sh
brew install ffmpeg git-lfs python
git lfs install
python3 -m pip install numpy opencv-python pillow matplotlib   # matplotlib 只在 check 模式用

git clone -b xunfei-ai4s-edit https://github.com/AndroidOne-io/tihuceshi-work.git
cd tihuceshi-work
git lfs pull          # 视频素材在 Git LFS 里，这一步不能省，否则 mp4 是几百字节的指针文件
```

### 1.2 Linux

`apt install ffmpeg git-lfs python3-pip`，其余同上。

### 1.3 自检

```sh
cd 科大讯飞/代码
mkdir -p /tmp/kx && python3 full.py align.json /tmp/kx stills   # 出一张关键帧拼图 /tmp/kx/stills.jpg，能出就说明环境 OK
python3 render_all.py 4 45 47                  # 试渲染 2 秒 → 科大讯飞/成片输出/试渲染_45-47.mp4
```

### 1.4 资源占用

- 每个渲染进程约 **2–2.5 GB 内存**（启动时会预先生成很多大图：工具墙、实验墙、背景等）。16 GB 内存开 4 个进程，32 GB 可开 6–8 个。内存不够进程会被系统直接杀掉（日志是空的）。
- 渲染速度大约每个进程每秒视频 4–8 秒（视机器而定）。

## 4. 数据流：一帧画面和一段声音是怎么来的

```
口播录音(3 个来源) ──ASR──> align.json(每个字在录音里的时间)
                                   │
shots.py(71 镜台词) ───────────────┤
PAUSE_OVR(停顿表) ─────────────────┤
                                   ▼
                    timeline.py：排时间线
                    ├─ shots[i]：start / end / dur / chars[(字, 成片时间)]
                    ├─ audio_pieces：每段录音 (源起, 源止, 放到成片的时刻, 来源)
                    └─ SUBS：字幕条
                                   ▼
                    full.py：EV 事件表（字/镜头 → 时刻）
                         │                         │
                         ▼                         ▼
          VIS[镜号](t) 画面函数            sound.py：MUSIC 配乐段 + sfx_plan 音效
          frame(t) = 画面+甩镜+字幕         build_audio() = 人声+配乐(自动闪避)+音效
                         │                         │
                         ▼                         ▼
                 逐帧 → ffmpeg(libx264)     混音 → loudnorm -14 LUFS
                         └──────── render_all.py 拼接合成 ────────┘
                                         成片.mp4
```

### 4.1 三种时间（最容易搞错的地方）

| 名字 | 含义 | 在哪用 |
| --- | --- | --- |
| **素材时间** | 录音 / 视频文件里的秒数 | `align.json`、`V10.get(秒)`、`audio_pieces` 的前两项 |
| **时间线时间 `t`** | 从第一句口播排起的时间，`shots[i]['start']`、`EV[...]` 都是这个 | 所有画面函数 `VIS[i](t)`、`sfx_plan` 里的时间 |
| **成片时间 `t_out`** | 视频文件里的秒数，`t_out = t + PRE`，`PRE = 1.6`（开头 1.6 秒黑场蓄力） | 命令行的起止秒、`check` 图的横轴、播放器里看到的时间 |

`frame(t_out)` 进来先减 `PRE`；`t < 0` 时是冷开蓄力（`hook`）。命令行 `render_all.py 4 45 47` 里的 45、47 是**成片时间**。

### 4.2 镜头结构 `S[i]`

`S = {镜号: dict}`，镜号 1–71（与 `shots.py` 顺序一致，从 1 开始）。每个 dict：

```python
dict(i=镜号, row=原表行号, text=台词, start=开始, end=结束, dur=时长,
     chars=[(字, 成片时间线时间), ...], kind=画面类型, pause=该镜后的停顿秒)
```

常用工具函数（full.py）：
- `wt(i, '词')`：第 i 镜里这个词**第一个字**被说出来的时刻。卡点全靠它，例如 `wt(36, '死亡之谷')`。
- `last_voice(i)`：第 i 镜最后一个字的时刻 + 0.35 秒（≈ 这句说完）。
- 英文词按整词算一个"字"（`nchars` 的正则：一个汉字 / 一串字母 / 一个数字各算一个）。

### 4.3 停顿 `PAUSE_OVR`

`full.py` 第 11 行：

```python
PAUSE_OVR = {1: 1.6, 8: 1.2, 11: 1.0, 13: 0.6, 15: 0.8, 17: 2.5, 18: 1.0, 25: 1.0, 36: 0.6, 47: 1.0, 50: 1.2, 60: 0.8, 70: 1.0}
```

含义：第 k 镜**口播说完后**插入多少秒停顿（口播停，画面和音乐继续）。停顿全部落在全屏画面上（大字、章节卡、数字），不落在真人出镜上——这是用户要求，见第 11 节。第 71 镜的结尾停顿写在 `shots.py` 里（1.5 秒）。改这里，后面所有画面/音乐/音效自动顺延。

### 4.4 事件表 `EV`

`EV` 是 dict，键是事件名，值是时间线时间。命名习惯：

- `cutN`：第 N 镜开始（= 切镜点）。
- 词事件：`boom`（攻克）、`create`（参与创造知识）、`afs`（AI for Science 片名）、`valley`（死亡之谷）、`n400`（400）、`real`（真实场景）……
- 派生事件：`ch_in = last_voice(25)`（01 化工研发章节卡出现）、`ch2_in = last_voice(50)`（02 生物医药章节卡）、`bridge = last_voice(18)`（转回国内）、`fall`（曲线栽下去）。
- 列表事件：`EV['mods']`（四个模块依次亮）、`EV['structs']`（五个结构依次亮）、`EV['sc']`（五个场景）。

定义位置：前 18 镜在 `full.py` 的 `EV = dict(...)`；之后每个 seg 文件开头 `EV.update(...)`。**新加动画时先加事件，再在画面和音效里引用它。**

### 4.5 画面：`VIS` 和 `frame`

- `VIS = {镜号: 函数(t) -> 帧}`。帧是 `float32` 的 `H×W×3` RGB 数组（0–255，可以超出，最后会 clip）。
- 同一个函数可以服务多个镜头（如 `v1011` 管 10–11 镜，`v_demo` 管 40–45 镜），函数内部自己看 `t` 落在哪。
- `frame_(t_out)`：找到当前镜 → `VIS[i](t)` → 切镜甩镜（`CUTS` 里的事件，前 0.1 秒、后 0.2 秒做方向模糊；`QUIET` 里的切点硬切不甩）→ 叠字幕。
- `frame(t_out)`：片尾最后 2.2 秒渐黑（`TAIL = 1.2` 秒片尾空余）。

### 4.6 真人出镜

- `cam_frame(t)`：按 `src_at(t, 'cam')` 把时间线时间换成出镜原片时间，取帧并**水平翻转**（原片镜像录的）。
- `host(z0, cards)(t)`：全屏真人，轻推镜（`z0` 起始缩放），`cards` 可在右侧弹卡片。
- `pip2(f, t, u, out)`：左下角圆形小窗（第 10–11、63–64 镜）。`out` 让小窗缩小消失——**口播一停原片画面就定住，所以口播结束前要把小窗收掉**（用户反馈过"人定住不好看"）。
- `HOST_SHOTS`（sound.py）：哪些镜是全屏真人，用来把配乐压得更低。
- 第 20 行（第 66–69 镜）只有声音克隆，没有出镜画面，所以这几镜全部用画面顶。

### 4.7 字幕

- 来自台词（`shots.py`），按标点切成 ≤15–16 字一条，跟着字时间出；说完 0.45 秒收（`sub_now`）。
- `NO_SUB = {13, 17, 36}`：大字镜头不出字幕（大字本身就是字）。
- `SUB_FIX`（timeline.py）：按用户实际念的修正字幕，如「科研院所」→「研究院所」。
- 样式：得意黑斜体白字细黑边，底部居中（`kx.subtitle`）。

## 5. 画面工具速查（kx.py / v4.py / seg3_vis.py）

| 函数 | 用法 |
| --- | --- |
| `put(f, img, cx, cy, a=1, scale=1, angle=0)` | 把 RGBA（PIL 或 ndarray）以中心点贴到帧上，`a` 透明度 |
| `text(s, 字体, 字号, 颜色, 字距)` | 生成文字 RGBA（PIL）。字体常量：`F_BLACK`（思源黑体 Black）、`F_SUB`（得意黑）、`F_NUM`（Bebas 数字）、`F_TITLE`（优设标题黑）、`F_BRUSH`（杨任东竹石体） |
| `shadow(img, r, off, a)` / `glow_rgba(img, col, r, k)` | 投影 / 外发光 |
| `metal('大字', 字号)` + `sweep(img, u)` | 金属拉丝大字 + 扫光（参与创造知识、AI for Science、真实场景） |
| `brush('死亡之谷', 字号)` | 毛笔飞白大字 |
| `number('400+', '', 字号, 颜色)` | 大数字 |
| `make_card(w, h, 'rect'/'circle', 圆角, 底色, 透明度, 标题, 图标, big=, title_size=, rim=, rim_col=)` | **半透明卡片/徽章**（不磨砂）。图标名：flask book medical gear home bulb wrench chart check doc list lock stack gem person factory |
| `bg_gild(backdrop=, dim=, leak=, leak_col=, k_leak=, key=, bokeh=)` | 石墨黑底 + 暖色漏光 + 光斑 + 颗粒 + 暗角；`backdrop` 可垫一张压暗的素材；`key` 用于缓存 |
| `card(img, w, radius, border, bcol)` | 截图/视频帧做成圆角卡片 RGBA |
| `persp(f, rgba, cx, cy, scale, ry, rx, rz, a, shadow_k)` | 把卡片绕 Y/X/Z 轴转一定角度后透视贴到帧上，返回映射矩阵 M |
| `dim_except(f, M, box, k)` | 透视后的截图上，除了 box（卡片坐标）以外压暗 |
| `hl_bar(f, x0, y0, x1, y1, u, 颜色, a)` | 高亮条从左往右扫 |
| `shot(图, box0, box1, hl, ry, rx, maxk, bgimg, rng_)`（full.py） | 截图镜头：铺满、倾斜、镜头从 box0 推到 box1、其余压暗、可选高亮 |
| `Vid(路径).get(秒)` | 顺序读视频帧（有缓存，往回跳或跳太远会 seek） |
| `cover(img, w, h)` | 等比裁切铺满 |
| `grade(img, sat, warm, dim)`（seg3） | 素材调色：去饱和、偏暖、压暗 |
| `foot(视频, 入, 出, speed, push, dim, sat)` / `shotfn(镜号, 片段…)`（seg3） | 空镜镜头：一个镜头里平均切几段素材，慢推 |
| `whip` `shake` `glitch` `zoom` `bloom` | 甩镜模糊、震动、故障闪、缩放、辉光 |
| `ease` `ease_out` `ease_in` `back_out` `seg(t,a,b)` `lerp` | 缓动；`seg` 把 t 映射到 0–1 |

## 7. 声音系统

### 7.1 人声

三个来源：`vo`（画外音 wav）、`cam`（出镜视频的音轨）、`r20`（声音克隆 mp3）。`timeline.py` 按 `align.json` 把需要的片段剪出来排到时间线上（`audio_pieces`），三个来源先做响度对齐（`GN`），片段两端 25 毫秒淡入淡出。

### 7.2 配乐（`sound.py` 的 `MUSIC`）

每一段是一行 `M(曲子, 曲内对齐点, 对齐到的事件, 起, 止, fin, fout, dip, ref, gap, under, host)`：

- **曲内对齐点 + 对齐到的事件**：曲子第 `src` 秒对准时间线的 `at`。例：`M(..futuristic-view.., 16.8, EV['cut38'], ...)` = 曲子 16.8 秒处「起来」的那一下对准第 38 镜（3.0 Pro 截图出现）。
- **起 / 止**：这一段在时间线上从哪到哪；`fin` / `fout` 淡入淡出秒数。
- **dip**：事件列表，重击前 0.25 秒音乐让开（如 400+、真实场景）。
- **ref**：曲子里用来测响度的 20 秒起点（避免拿安静前奏做参考导致整段过响）。
- **三档电平**（相对人声响度，dB）：
  - `gap`：停顿、大字、纯画面时，默认 −4（抬上来接近人声）
  - `under`：画面配口播时，默认 −16
  - `host`：真人出镜口播时，默认 −30（几乎退到背景）
- 闪避逻辑（`full.py` 的 `build_audio`）：检测口播 → 包络（起 60 毫秒、落 350 毫秒，**说话间换气 < 0.45 秒不抬音乐**）→ 在 gap 与 under 之间插值；真人镜头整段固定 host 电平，不随换气起伏。

选曲依据：测过每首在人声频段（300–3400 Hz）的能量占比，越低越不抢词；节奏密的、旋律强的不放口播下面。候选但没用的：Marimba、Curious Circuits（太密）、Hopeful Warm Music（人声频段占 81%）等，都在 `音乐素材/` 里。

### 7.3 音效（`sound.py` 的 `sfx_plan()`）

一行一个 `(名称, 时间线时间, 音效键, 音量)`。音效键：`rise`（上升）、`rrise`（反向上扬）、`whoosh`（转场）、`swish`（轻风声）、`gate`（门控重击）、`thud`（闷击）、`dong`（咚·重磅）。

- **对齐方式**：自动测每个音效文件的峰值位置，把**峰值**对准事件时刻（不是文件开头）。
- **原则**：大重击 `dong` 只给 6 个大时刻（攻克、参与创造知识、AI for Science、死亡之谷、400+、真实场景）；转场声只在换段落、换大画面；徽章、卡片用很轻的 `thud`（0.1–0.15）；同一段里素材换素材不加声。

### 7.4 母带

人声 + 配乐 + 音效相加 → `ffmpeg loudnorm I=-14 TP=-1.5` → 整片 −14 LUFS。

### 7.5 重新对齐口播（一般不需要）

只有换了录音才要。需要 sherpa-onnx v1.13.8 静态版、模型 `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17`、`silero_vad.onnx`（GitHub k2-fsa/sherpa-onnx releases），放到 `align.py` 第 3 行 `ASR` 指的目录，然后 `python3 align.py align.json`。`align.py` 里的 `TAKES` / `CAM` 列表写了每行台词选用录音的哪一条、哪一段。

## 9. 常见修改配方

### 9.1 改某处停顿长短

改 `full.py` 第 11 行 `PAUSE_OVR` 里对应镜号的秒数。不在表里的镜头默认停顿来自 `shots.py` 第 9 项（大多是 0）。改完重新渲染整条（停顿会让后面全部顺延）。

### 9.2 换某一段配乐

1. 把曲子放进 `音乐素材/`。
2. 测它的响度曲线，找"起来"的那一下或段落边界（可以用 ffmpeg 转 16 kHz 单声道后按秒算 RMS）。
3. 改 `sound.py` 对应那行：文件名、`src`（曲内对齐点）、`at`（对齐到哪个 EV 事件）、`ref`（找一段有代表性的 20 秒）。
4. `check` 模式看图和电平报告：画面口播时配乐应比人声低 15–19 dB，真人口播低约 30 dB，停顿时低 4–6 dB。
5. 只改声音时不必重渲画面：`audio` 模式出整条音轨，用 ffmpeg 把新音轨换到已渲染的视频上（`-map 0:v -map 1:a -c:v copy`）。

### 9.3 加 / 删一个音效

在 `sound.py` 的 `sfx_plan()` 里加一行 `('名称', EV['事件'] 或 wt(镜号,'词'), '音效键', 音量)`。新音效文件放 `音乐素材/旧库/音效/`，并在 `sound.py` 的 `SFX` 字典里登记键名 → 文件名。

### 9.4 改某个镜头的画面

在对应文件里找 `VIS.update({...})` 或 full.py 的 `VIS = {...}`，找到镜号对应的函数，改函数。改完用 `stills` 模式看静帧（把要看的时间点写进 `seg6_vis.py` 末尾的 `STILLS`，见第 8 节），满意再渲染。

### 9.5 替换占位素材（例如两家 logo）

第 37 镜 `seg4_vis.py` 的 `P_XF` / `P_DL` 现在是名字 + 图标徽章。拿到 logo 后：用 `imread` 读 PNG（保留透明），缩放后用 `put` 贴到 `make_card` 生成的圆形徽章上（或直接做成圆形 logo 徽章），替换这两个变量。`P_XF` 还在第 56 镜被复用（讯飞徽章压进来）。

### 9.6 加一个新的动画事件

1. 在对应 seg 文件开头 `EV.update(新事件=wt(镜号, '词'))`。
2. 画面函数里用 `seg(t, EV['新事件'], EV['新事件'] + 0.3)` 控制出现。
3. `sfx_plan()` 里加音效对准 `EV['新事件']`。

### 9.7 改字幕错别字 / 按实际念的改

改 `timeline.py` 的 `SUB_FIX`（`{'原文': '显示为'}`），或直接改 `shots.py` 台词（台词会参与对齐，改字数可能影响卡点，优先用 SUB_FIX）。

### 9.8 新增 / 删除镜头

改 `shots.py` 的 `SH`（注意镜号是按顺序自动编的，插入后后面全部 +1，所有 `S[镜号]`、`wt(镜号,…)`、`VIS` 键、`PAUSE_OVR` 键、`HOST_SHOTS` 都要跟着改）。尽量不要增删镜头，能在现有镜头里改就在里面改。

## 10. 改完怎么验证

1. `stills`：看关键帧有没有穿帮（文字太小、卡片挡字幕、素材水印、黑边）。
2. `check`：看红线（音效）是不是对准画面事件、配乐在真人段是不是够低、停顿处音乐有没有抬起来。
3. 试渲染改动附近 5–10 秒：`render_all.py 4 起 止`，真的看一遍、听一遍。
4. 整条渲染后看 `render_all.py` 打印的总帧数是否等于「应为」帧数（接缝不丢帧）。
5. 交付给用户时分段给（每段约 30–45 秒），每个文件 < 30 MB。

## 11. 用户的硬性要求（改任何东西都必须遵守）

### 11.1 沟通

- **全程用中文。**
- **用户中途发消息，先回复再继续干活**，不要闷头做。
- **改之前先说明要改什么、为什么、怎么改**；不说就改，用户会认为是糊弄。拿不准的（尤其选曲、风格）先给方案和理由，让用户拍板。
- 渲染慢，**不要一次性渲染整条给用户看**，给 30 秒左右的片段或截图；用户也可以在本地渲染。
- 交付时说清楚这一版改了什么。

### 11.2 画面

- 学**小Lin说**的方法和节奏，不照抄她的配色；要自己设计得更好看。
- **不要小字、小卡片。** 画面上的文字只允许：字幕、徽章里的名字、单独出现的大标题。
- **大标题单独出现**，不压在人脸或素材正中。
- **背景不能是纯色平铺**（用 `bg_gild`：石墨黑 + 香槟金漏光 + 光斑 + 颗粒）。
- **截图必须处理**：铺满、透视倾斜、其余压暗、重点高亮；**裁掉水印和素材自带字幕**。
- **卡片半透明，不要磨砂玻璃**；颜色要干净好看（不要棕色、土黄）。
- 香槟金只给数字和重点。
- 解释性动画要多，抽象概念要画出来（流程、对比、数量）。
- 真人出镜原片是镜像录的，代码里已翻回。
- 真人画面定住（口播停了）就别留在画面上（小窗要收掉）。

### 11.3 节奏与停顿

- 停顿只放在全屏画面（大字、章节卡、数字、重要揭示）上，**不放在真人出镜上**。
- 停顿是"按需"的，不凑数量；太长用户会嫌拖（目前大字后约 0.6 秒）。

### 11.4 声音

- **声音和画面必须完全对上**（用户说这是最重要的）：每个音效都对准画面事件。
- BGM 要合适、要听得见，但**真人出镜时 BGM 要压到几乎听不见**。
- 不同场景用不同的曲子或不同音量；重击前音乐让开；音效克制，不泛滥。
- 选曲要说出理由；库里没合适的就告诉用户需要什么，给搜索方向或链接，用户去找。

## 13. 坑

- **Git LFS**：没 `git lfs pull` 的话 mp4 是指针文件，`cv2` 读出来是空帧，渲染会报 `NoneType` 错。
- **内存**：每个进程 2–2.5 GB；进程无声无息消失、日志为空，基本是被系统 OOM 杀了，减少进程数。
- **时间单位**：画面函数和 EV 都是时间线时间；命令行和播放器是成片时间（多 1.6 秒）。
- **分段渲染**：一定按帧号切（`render_all.py` 已处理），不要用浮点秒数 `int(秒*30)`，会差一帧。
- **`Vid.get` 的缓存**：顺序往后读很快；往回跳或一次跳超过 90 帧会 seek，速度变慢但结果正确。
- **配乐参考段 `ref`**：如果对齐点在曲子安静处（前奏/尾声），一定要单独指定 `ref` 到有代表性的段落，否则增益算出来会过大，整段配乐爆响。
- **画面函数要是纯函数**：只依赖 `t`，不依赖上一帧的状态（多进程分段渲染时每段是从中间开始的）。缓存可以有，但缓存内容不能随时间变。
- **字体**：全部在 `交接资料/7_字体/`，代码用相对路径；不要改回系统字体路径。
